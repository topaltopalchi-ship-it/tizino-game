# وضعیت واقعی پیشرفت تیزینو

این درصدها برآورد مدیریتی از وضعیت مخزن هستند، نه نتیجهٔ اجرای Unity یا آزمون دستگاه. «کد اولیه موجود» به معنی آماده‌بودن قابلیت برای انتشار نیست.

## کارهای بعدی به ترتیب اولویت

1. اجرای بررسی‌های ایستای CI برای منطق لول‌ها و همگامی بانک Resource؛ سپس ایجاد/بازکردن پروژهٔ کامل Unity 6 URP و رفع خطاهای واقعی کامپایل.
2. ساخت و ذخیرهٔ صحنهٔ `Stage01_Bridge` و اتصال کنترلر و فایل JSON.
3. اجرای مرحله در Unity Editor؛ بررسی بازسازی مرحله، پاسخ درست/غلط و چیدمان رابط.
4. انتخاب فونت مجاز و افزودن راهکار آزموده‌شده برای شکل‌دهی فارسی و راست‌به‌چپ.
5. افزودن کلیپ‌های صوتی واقعی و بررسی پخش/تکرار/قطع صدا.
6. ساخت APK آزمایشی، نصب روی دستگاه Android و ثبت خطاها و کارایی.
7. تنها پس از پایدارشدن نمونه، توسعهٔ مراحل بعدی، ذخیره‌سازی، حریم خصوصی و هرگونه سرویس آنلاین.

## تعریف «تمام‌شده»

یک قابلیت تنها وقتی تمام‌شده تلقی شود که کد آن بازبینی شده، در پروژهٔ واقعی Unity کامپایل شده، رفتار آن در Editor بررسی شده و هر جا لازم است روی Android آزمایش شده باشد. ثبت کد یا مستند به‌تنهایی اثبات نمی‌کند که قابلیت در بازی اجرا می‌شود.


## وضعیت پس از بررسی CI در ۲۰۲۶-۱۰-۲۳

- تست خودکار بانک سؤال و پیش‌نمایش: **سبز** در commit `c0e4c63`.
- بررسی ایستای پیش‌نمایش: **سبز** در همان commit.
- انتشار Pages: **مسدود**؛ لاگ GitHub خطای `Resource not accessible by integration` را هنگام ساخت سایت Pages نشان می‌دهد. گردش‌کار نمی‌تواند با توکن فعلی خودش قابلیت Pages مخزن را فعال کند. مالک مخزن باید یک‌بار از مسیر **Settings → Pages → Build and deployment → Source: GitHub Actions** آن را فعال کند؛ پس از آن اجرای workflow دوباره قابل بررسی است.
- تغییر workflow برای تلاش خودکار فعال‌سازی Pages در commit `cab5b30` انجام شد، اما به‌دلیل محدودیت دسترسی GitHub شکست خورد؛ این را موفقیت انتشار حساب نکنید.
- پروژهٔ کامل Unity و APK همچنان ساخته/تأیید نشده‌اند. تست‌های Node، جای کامپایل Unity، اجرای صحنه یا نصب روی Android را نمی‌گیرند.

## برآورد تکمیل محصول

این برآوردها دو مسیر متفاوت را جدا می‌کنند تا آماده‌بودن پیش‌نمایش با آماده‌بودن اپ اشتباه نشود:

| خروجی | برآورد فعلی | دلیل |
|---|---:|---|
| پیش‌نمایش وب پایهٔ اول و دوم | 75% | بانک سؤال و منطق تعامل تست خودکار دارند؛ انتشار Pages هنوز مسدود است و آزمون کاربری/دسترسی‌پذیری کامل نشده |
| نمونهٔ فنی Unity قابل اجرا | 25% | کد و راهنما موجود است، اما پروژه/صحنهٔ کامل و کامپایل Unity تأیید نشده |
| اپ Android قابل نصب (APK) | 10% | مسیر ساخت مستند شده، ولی APK واقعی و آزمون دستگاه وجود ندارد |
| محصول کامل هدف‌گذاری‌شده (بازی سه‌بعدی آموزشی) | 15% | بخش عمدهٔ مدل‌ها، انیمیشن، مراحل کامل، RTL آزموده‌شده، ذخیره‌سازی، صدا و QA دستگاه هنوز باقی است |

**برای رسیدن به اولین APK آزمایشی:** مهم‌ترین کارهای باقی‌مانده ساخت/بازکردن پروژهٔ Unity 6 با Android Build Support، واردکردن اسکریپت‌ها و بانک‌ها، ساخت صحنهٔ واقعی، رفع خطاهای کامپایل، تنظیم آیکون اصلی دقیقاً بدون تغییر، سپس ساخت و نصب APK و آزمون روی دستگاه است. درصدها برآورد برنامه‌ریزی‌اند، نه اندازه‌گیری خودکار.
